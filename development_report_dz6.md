# Лабораторная работа 6

Лабораторная работа 6
Настройка CI/CD и интеграция сервисов

Цель работы: организовать автоматическую проверку и развёртывание TaskFlow, интегрировать OAuth2 и аналитику, настроить аудит безопасности, health checks и структурированные логи.

1. Исходный проект
В качестве основы используется проект TaskFlow из лабораторной работы 5: FastAPI, PostgreSQL, React/Vite и Docker Compose. Существующие CRUD задач и авторизация по JWT сохранены.

2. CI/CD
Подготовлен `.github/workflows/ci-cd.yml` на GitHub Actions: установка зависимостей; проверки Ruff, pytest, TypeScript, Vitest, Vite build; аудит пакетов `pip-audit` и `npm audit`; SSH-деплой при push в main после успешных проверок. Для развёртывания необходимы GitHub Secrets DEPLOY_HOST, DEPLOY_USER, DEPLOY_SSH_KEY и DEPLOY_PATH, готовый сервер с Docker Compose и `.env`. Реальный запуск в GitHub пока не подтверждён.

3. Аудит безопасности
Проведён статический обзор приложения по OWASP: SQLAlchemy для параметризованных запросов, изоляция задач по user_id, конфиденциальность секретов, JWT, CSRF state Google OAuth и XSS в React. Результаты и остаточные риски (JWT в localStorage, brute force, привязка аккаунтов по email) внесены в `security_audit.md`. Автоматические сканеры включены в CI, но результаты их выполнения ожидаются.

4. Интеграция OAuth2
Реализованы Google OpenID Connect через Authlib и эндпоинты `/auth/google/login`, `/auth/google/callback`, `/auth/google/exchange`. Добавлена кнопка входа через Google. Временный одноразовый ticket обменивается на JWT; сам JWT через URL не передаётся. Для запуска нужны Google Client ID и Secret, OAuth redirect URI и HTTPS при публичном развёртывании. Проверка у реального провайдера требует этих реквизитов.

5. Интеграция аналитики
Добавлена условная загрузка Яндекс.Метрики при заданном VITE_METRIKA_ID и события `task_created`, `task_updated`, `task_deleted`. Для подтверждения доставки требуется счётчик Метрики и проверка DevTools Network.

6. Мониторинг
Добавлен `/health/ready` с запросом SELECT 1 к PostgreSQL; сохранён `/health`. Предусмотрен запланированный GitHub workflow проверки внешнего HEALTHCHECK_URL каждые 15 минут. Действующие уведомления требуют адреса публичного развёртывания и настройки оповещений GitHub.

7. Логирование
Логи backend приведены к JSON (time, level, logger, message); сохраняется вывод в stdout Docker. Подготовлены AI-промпты для анализа типичных проблем по логам; реальную централизованную систему логов можно подключить позднее.

8. Проверки
В проект добавлены дополнительные API-тесты: доступность БД по readiness, отклонение неверного одноразового OAuth-билета, недоступность Google OAuth без конфигурации. Синтаксис main.py проверен командой py_compile. Полный pytest и npm build в рабочей среде не прошли из-за отсутствия сетевого доступа к пакетам Authlib и npm, а не из-за установленной ошибки приложения. Фактических результатов green pipeline или деплоя нет.

9. Состав сдачи
Исходники TaskFlow, workflows, `integration_documentation.md`, `security_audit.md`, `ai_workflow.md`, README, `.env.example` и тесты. Для окончательного подтверждения необходимо выполнить CI на GitHub, включить OAuth и Метрику, проверить публичный деплой и предоставить скриншоты.

Вывод: подготовлен воспроизводимый каркас CI/CD и интеграций, но для статуса «Принято» необходимо настроить внешние сервисы и подтвердить работу pipeline/деплоя фактическими логами и скриншотами.
